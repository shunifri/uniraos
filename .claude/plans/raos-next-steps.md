## 二、关键洞察：表单引擎是当前的"战略瓶颈"

表单引擎的四个目标揭示了核心矛盾：

> **当前实现 = "AI 对话里的输入面板"**
> **目标要求 = "能接管传统业务系统的平台级表单基础设施"**

差距在于：
- 目标1（接管传统业务）→ 缺原生组件、缺主题适配、缺独立页面
- 目标2（数据采集）→ 缺跨字段校验、缺条件 schema、缺草稿保存
- 目标3（便捷回复）→ Chat 内嵌体验天花板，需要"逃逸到独立页面"的选项
- 目标4（流程承载）→ 缺审批操作集成、缺流程推进联动、缺独立任务页

**更深层的问题**：表单引擎的深化需要其他模块配合——审批中心、Workflow 任务页、独立路由、主题系统。这些模块恰恰是当前最薄弱的环节。

因此，**下一步不应只修表单，而应以"表单引擎深化"为牵引，同步补齐审批中心、Workflow 前端、主题适配这三个配套模块**。

## 三、行动计划

### Phase 1：体验断层修复（2 周）
**目标：让用户能"正常用"，消除最明显的体验断裂**

| 序号 | 任务 | 说明 | 优先级 |
|------|------|------|--------|
| 1.1 | **Select/Radio/Checkbox 支持原生 Antd 变体** | `ui:props.variant` 真正生效：`dropdown`/`radio`/`checkbox`/`segmented`/`tag` 五选一 | P0 |
| 1.2 | **表单主题接入 Antd ThemeProvider** | 去掉硬编码颜色，使用 antToken 或 CSS 变量，支持暗色模式 | P0 |
| 1.3 | **审批中心独立页面** | `/approvals` 不再跳转到 `/chat`；列表（待我审批/我已审批/我发起的）+ 详情（表单渲染 + 审批意见 + 操作按钮） | P0 |
| 1.4 | **Workflow 任务表单页面** | `/workflow/tasks/:taskId` 独立页面，渲染表单 + 审批操作栏 + 提交后推进流程 | P0 |

### Phase 2：功能补全（2-3 周）
**目标：让表单引擎从"能用"到"好用"**

| 序号 | 任务 | 说明 | 优先级 |
|------|------|------|--------|
| 2.1 | **跨字段校验** | JSON Schema 扩展 `x-crossValidation`：支持表达式如 `{{endDate}} > {{startDate}}` | P1 |
| 2.2 | **条件 schema（if/then/else）** | 字段根据其他字段值动态显示/隐藏/改变类型 | P1 |
| 2.3 | **独立表单中心** | 表单定义列表页 + 表单填写页（独立路由，不依赖 Chat/Workflow）+ 表单数据查看页 | P1 |
| 2.4 | **表单草稿自动保存** | 定时保存到 localStorage 或后端，恢复时提示"是否继续上次填写" | P1 |
| 2.5 | **后端 schema 校验** | `form-service.ts` 保存前校验 schema_json 是否符合 `RaosFormSchema` | P2 |
| 2.6 | **移除 ConfirmCard legacy `fields` 实现** | 统一走 schema，减少维护负担 | P2 |

### Phase 3：架构治理（持续）
**目标：长期健康，不影响新功能交付**

| 序号 | 任务 | 说明 | 优先级 |
|------|------|------|--------|
| 3.1 | **inbox + scheduler + services 测试补全** | 至少覆盖核心路径 20 个测试 | P1 |
| 3.2 | **server.ts 拆分** | Skill 注册 → `bootstrap/skills.ts`；Provider 生命周期 → `bootstrap/providers.ts`；路由已拆分，清理剩余 inline handler | P2 |
| 3.3 | **构建产物清理** | `src/ui/assets/` 加 `.gitignore`，CI 中 build | P2 |
| 3.4 | **Chat 页面职责拆分** | 审批跳转到独立页面；表单填写支持"在新页面打开"；Chat 只保留纯对话 | P3 |
| 3.5 | **Form/Workflow schema 统一** | 评估是否将 Workflow 表单绑定也迁移到 `RaosFormSchema` 标准 | P3 |

## 四、先做哪件？

建议从 **Phase 1 的 1.1 + 1.2 + 1.3** 开始：

1. **1.1（原生组件）+ 1.2（主题适配）** 是表单引擎的"面子工程"——没有这两个，表单永远像 Demo，接不了传统业务。
2. **1.3（审批中心）** 是表单引擎的"场景出口"——审批是表单最重要的企业级场景，没有独立审批中心，表单数据填了无处可去。

这三件事做完，表单引擎才算真正"立住"，后续的功能补全才有意义。
