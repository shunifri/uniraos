# 继续教育招生，80% 的重复咨询可以用 RAOS 自动解决

成人学历提升、职业资格培训、在职研究生……继续教育的咨询有个特点：**问题多、重复率高、用户决策周期长**。

"我 35 岁了还能报本科吗？"
"这个证书国家承认吗？"
"线上学习要不要打卡？"
"学费能不能分期？"

这些问题的答案，招生老师每天要重复几十上百遍。我们尝试用 **RAOS（Recursive Agent Operating System）** 搭了一个继续教育招生咨询助手，效果出乎意料地好。

## 一、先解决最关键的问题：交互要足够友好

继续教育的咨询对象很多是职场人士，时间碎片化，对 AI 未必熟悉。他们需要的不是冷冰冰的百科回答，而是一个**有耐心、听得懂、会引导**的顾问。

RAOS 的 Agent 可以配置成亲切的对话风格：

- 用口语化表达，避免官方套话
- 遇到模糊问题时，主动追问学历、工作年限、学习目标
- 用户表达焦虑时，先安抚再解答

比如用户问"这个证有用吗？"，助手不会直接甩一堆介绍，而是先反问："您是想用来跳槽、晋升，还是考编？不同用途含金量侧重点不一样。"

## 二、做在线咨询，大家都会踩的几个坑

如果你真动手做过一个继续教育在线咨询系统，大概率会经历这几个阶段：

### 第一阶段：堆 FAQ

把所有常见问题整理成问答对。一开始够用，但很快就发现——用户根本不按 FAQ 的问法来。

有人写"我三十二了还能不能升本科？"，FAQ 里是"成人高考报名条件是什么？"，匹配不上。然后你不断增加同义问法，最后 FAQ 膨胀到几千条，维护起来像噩梦。

### 第二阶段：上 RAG

把招生简章、专业介绍这些文档切片，用户提问时检索最相关的片段。这比 FAQ 灵活多了，但复杂问题还是搞不定。

比如用户问："我 32 岁、大专、想周末上课，推荐什么专业？"

RAG 会分别找到"32岁""大专""周末上课""专业介绍"几个片段，然后拼成一段答案。听起来像是回答了，但用户真正想要的"推荐"并没有给出来。因为它只会**找相关内容**，不会**综合推理**。

而且用户如果接着问"那个专业学费多少？怎么缴费？"，RAG 每次都要重新检索，上下文很容易丢。聊了三轮，用户还得重复自己的情况。

### 第三阶段：画流程图

于是开始用流程编排工具，把咨询过程画成一棵树：

```
问候 → 问学历 → 问专业意向 → 推荐课程 → 引导报名
```

流程固定的时候确实很清晰。但继续教育的咨询哪有这么规矩？

用户可能第一句话就是"你们那个证靠谱吗？"，也可能聊到一半突然问"我同事报的那个专业还能报吗？"，还有可能已经报完名了来问"什么时候开课"。

流程图画得越细，分支就越多，后期改起来越痛苦。稍微偏离预设路径，AI 就开始答非所问。

到最后你会发现：**你不是在做一个聪明的助手，而是在维护一棵越来越复杂的决策树。**

## 三、RAOS 为什么不一样？因为它是"生成"出来的

RAOS 不是再走"文档切片 + 固定流程"的老路，而是把能力拆成一个个 **Skill**，让 Agent 根据对话自己决定怎么组合。

还以那个复杂问题为例："我 32 岁、大专、想周末上课，推荐什么专业？"

RAOS 的 Agent 会这样处理：

- 调用**信息提取 Skill**，把"32岁""大专""周末上课"这些条件抓出来
- 调用**知识图谱 Skill**，匹配符合条件的专业
- 调用**对比分析 Skill**，把候选专业的学费、学制、就业方向排出来
- 调用**友好表达 Skill**，用口语化方式给出推荐

每一步都是动态决定的，不需要你提前画流程图。

**更重要的是，这个招生咨询应用本身，是可以直接生成的。**

在 RAOS 里，应用生成不是只输出一个对话机器人，而是会一次性生成应用所需的多个维度：

### 1. 生成 Skill

你说："需要一个能查询招生简章、推荐专业、解答学费问题的咨询 Skill。"

RAOS 会自动生成对应的可执行 Skill，包括参数定义、调用逻辑、知识库检索方式、输出格式，甚至自动补上一组测试用例。

### 2. 生成表单

如果咨询过程中需要收集学员信息，比如"预报名表"，RAOS 会根据描述直接生成表单：

- 字段：姓名、手机号、学历、工作年限、意向专业、学习形式
- 校验：手机号格式、学历与专业的匹配检查
- 联动：选了"专升本"才显示"原学历专业"，选了"周末班"才提示上课时间

不用手动画表单、配规则。

### 3. 生成知识库分类

你说："把招生资料分成招生政策、专业介绍、学费缴纳、学习安排、毕业证书这几类。"

RAOS 会自动构建知识库的分类体系、提取规则和检索策略。后续上传招生简章、专业目录、学费文件时，会自动归到对应分类，Agent 回答时也知道该去哪个分类查。

### 4. 生成流程

如果业务需要固定流程，比如"意向登记 → 专业推荐 → 费用说明 → 报名引导 → 转人工确认"，RAOS 会根据描述生成工作流：

- 每个节点该调用哪个 Skill
- 什么条件下分流
- 什么情况下转人工
- 每一步的输出该展示成对话、表单还是卡片

流程不是死板的 if-else，而是可以和 Agent 的动态推理结合：有明确流程就走流程，遇到模糊问题就回到 Agent 自由对话。

### 5. 生成页面与交互

RAOS 还能根据描述生成前端页面：咨询对话框、专业对比卡片、报名表单页、知识库文档展示页。页面会和后端的 Skill、流程、数据自动对接。

也就是说，你说一句：

> "我要一个继续教育招生咨询应用，能自动回答招生政策、推荐专业、收集报名信息，语气亲切，遇到政策问题要谨慎。"

RAOS 会同时生成 Skill、表单、知识库分类、流程和页面。后续业务变了，也不需要重写整个应用，只需要对某个维度重新生成或调整。

这才是 RAOS 和传统 RAG、流程编排工具的本质区别：后者是**配置出一个应用**，RAOS 是**生成并持续演化一个应用**。

## 四、DocMind + 知识图谱，招生资料自己"活"起来

继续教育的招生材料很杂：招生简章、专业目录、学费说明、课程表、毕业证书样本、合作院校文件……

RAOS 的 **DocMind** 可以直接解析 PDF/Word，自动提取关键信息。招办老师上传文件就行，不用一条条手工录入 FAQ。

更关键的是，RAOS 会用**知识图谱**把信息串起来：

- 专业 → 对口证书 → 就业方向
- 学习形式 → 上课节奏 → 考试安排
- 学员背景 → 推荐专业 → 预计毕业时间

这样当用户问"A 专业和 B 专业哪个更适合我转行？"时，Agent 不是分别介绍两个专业，而是在图谱上走一圈，给出一个真正有理有据的对比。

## 五、网络搜索，让信息不过时

继续教育政策、报名时间、合作院校动态经常变化。如果 AI 只会读本地文档，很容易给出过期答案。

RAOS 可以接入**网络搜索 Skill**，回答前先检索最新官方通知：

- "今年成人高考报名截止时间"
- "某专业是否还在招生"
- "最新学费标准"

搜到的结果会作为上下文参与推理，并标注信息来源，避免 AI 张口就来。

## 六、提示词约束，守住合规底线

招生咨询最怕 AI 乱承诺："包过""免考拿证""一年毕业"……一旦说出口，合规风险极大。

RAOS 支持在应用层配置**提示词约束**：

- 明确回答边界：能说什么、不能承诺什么
- 强制免责声明：涉及政策、学费等敏感信息，提示"以官方最新通知为准"
- 风格约束：正式/亲切/严谨，统一口径
- 转人工规则：遇到政策争议、投诉倾向、特殊申请，自动交给真人老师

这样每个 Agent 都是一个"戴了紧箍咒"的专业顾问，既高效又安全。

## 七、长周期跟进，记住每个学员

继续教育从咨询到报名往往要几周甚至几个月。用户今天问报名条件，下周问学费，下个月问开课时间。

RAOS 的**记忆系统**会保存每次对话的关键信息：

- 学历背景
- 意向专业
- 学习时间偏好
- 犹豫点

下次用户再来，Agent 能直接接着聊："您上次提到工作日晚上有时间，我给您推荐两个适合的线上专业。"

## 八、管理后台：问答式看数据、出图表、导数据（本质都是 Skill）

AI 助手跑起来之后，招办管理者最关心的其实是另一件事：**今天有多少人来咨询？大家都问什么？哪些专业最热门？转化情况怎么样？**

在 RAOS 里，查数据、出图表、导数据并不是写死的后台功能，而是一组**数据 Skill**。管理员可以直接用自然语言向 Agent 提问，Agent 会调用对应 Skill 完成查询、可视化或导出。

### 问答式查数据

不用翻后台、点菜单，直接问：

- "今天有多少人来咨询？"
- "本周最热门的五个专业是什么？"
- "现在有多少高意向学员还没被跟进？"
- "对比上个月，报名转化率有什么变化？"

Agent 会实时查询数据库，把结果用自然语言或表格形式呈现出来。

### 问答式出图表

想要图表也不用打开 BI 工具，直接说：

- "画一张近 30 天咨询量趋势图"
- "看一下咨询专业分布的饼图"
- "帮我生成一个从咨询到缴费的转化漏斗"
- "哪个时段咨询最集中，用热力图展示"

Agent 调用图表 Skill 生成对应可视化，直接展示在对话里。

### 问答式导数据

需要导出数据时，一句话就能搞定：

- "导出本月所有会话记录，我要做质检"
- "把高意向学员列表导出成 Excel，发给招生老师"
- "导一份热门问题统计，用来更新 FAQ"
- "生成本周转化报表 CSV"

数据导出为 Excel / CSV，可直接对接已有的招生管理系统或汇报流程。

### 为什么这是 Skill？

在 RAOS 中，查数据、画图表、导数据都被封装成独立的 Skill：

- 可以被 Agent 调用
- 可以被组合进更大的流程
- 可以被权限控制
- 可以被复用、扩展、定制

这意味着，管理者不需要学习复杂后台，直接用说话的方式就能完成数据查询、可视化和导出。招生老师、市场负责人、甚至校领导，都能用同一套 Agent 获得自己想要的数据视图。
